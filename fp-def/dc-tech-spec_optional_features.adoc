NetApp 支持多个可选组件，可进一步增强 FlexPod 数据中心架构。以下各小节概述了可选组件。


NOTE: SAN 启动是可选的，但强烈建议使用，因为它允许在硬件升级或更换期间移动服务器配置文件。



[[iscsi-boot-option]]
== iSCSI 启动选项

iSCSI 引导选项的最低要求包括：

* 在 NetApp 存储控制器上激活的 iSCSI 许可证 / 功能
* NetApp 存储控制器 HA 对中每个节点上的一个双端口 10Gbps 以太网适配器
* Cisco UCS 服务器中支持 iSCSI 启动的适配器


下图显示了基于 IP 的 iSCSI 配置的带有 X 系列模块化系统和 C 系列机架式服务器的 FlexPod Datacenter 示例。

image:dc-tech-spec_image15.png["FlexPod Datacenter，适用于基于 IP 的 iSCSI 连接"]

有关此配置的详细信息，请参见 link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 设计指南"^]。



[[fc-boot-with-cisco-mds]]
== 使用 Cisco MDS 启动 FC

为了通过使用专用 SAN 网络提供更高的可扩展性，FlexPod 通过 Cisco MDS 交换机支持 FC。通过 Cisco MDS 的 FC SAN 引导选项具有以下许可和硬件要求：

* 每个 NetApp 存储控制器至少两个 FC 端口；每个 SAN 网络结构一个端口
* 每个 NetApp 存储控制器上的 FC 许可证。
* Cisco UCS 服务器中具有 FC 引导功能的适配器。


下图显示了采用 X 系列模块化系统和 C 系列机架式服务器的 FlexPod Datacenter 示例，该配置基于 FC 的 SAN，并使用 MDS 交换机。

image:dc-tech-spec_image16.png["FlexPod Datacenter，适用于基于 FC 的 SAN 连接"]

有关此配置的详细信息，请参见 link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 设计指南"^]。

[[end-to-end-fc-nvme]]
== 端到端 FC-NVMe

端到端 FC-NVMe 可无缝扩展客户现有的 SAN 基础架构，实现实时应用，同时提高 IOPS 和吞吐量，并降低延迟。现有的 32G FC SAN 传输可用于同时传输 NVMe 和 SCSI 工作负载。

有关此配置的详细信息，请参见 link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 设计指南"^]。



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS X-Series Direct 和直连 AFF/ASA/FAS，适用于基于 FC 和 IP 的 SAN

NetApp 存储控制器可以直接连接到 Cisco UCS 交换矩阵互联，而无需任何上游 SAN 交换机。FlexPod 支持使用 UCS X-Series Direct 进行 FC 和 iSCSI 启动。

许可和硬件要求如下：

* 需要在 NetApp 存储控制器上获得协议许可证。
* 服务器上需要 Cisco UCS 适配器（启动器）。有关支持的 Cisco UCS 适配器的列表，请参见 NetApp https://imt.netapp.com["IMT"^]。
* NetApp 存储控制器上需要一个目标适配器。


下图显示了基于 IP 的 SAN 的 UCS X-Series Direct 和直接连接 ASA 拓扑。

image:dc-tech-spec_image13.png["UCS X-Series Direct 和直连 ASA 拓扑（适用于基于 IP 的 SAN）"]

* 注： *

* Cisco UCS 配置为以太网交换模式。
* 从目标到互联阵列的 iSCSI 端口会配置为 iSCSI 数据的以太网存储端口。


下图显示了基于 IP 和基于 FC 的 SAN 的 UCS X-Series Direct 和直接连接 ASA 拓扑。

image:dc-tech-spec_image14.png["UCS X-Series Direct 和直连 ASA 拓扑，适用于基于 IP 和基于 FC 的 SAN"]

* 注： *

* Cisco UCS 配置为 FC 交换模式。
* 从目标到互联阵列的 FC 端口配置为 FC 存储端口。


有关此配置的详细信息，请参见 https://www.netapp.com/pdf.html?item=/media/135828-flexpod-san-ucs-xdirect-asa-nva-deploy-guide.pdf["FlexPod SAN 解决方案，采用 Cisco UCS X-Series Direct 和 NetApp ASA"^]。


NOTE: 上述示例使用 NetApp ASA 存储控制器，但 NetApp AFF 和 FAS 存储控制器也支持相同的配置。



[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP with VXLAN 多站点交换矩阵解决方案由两个 FlexPods 组成，位于相距一定距离的两个站点，但连接并配对在一起，可提供高可用性、高灵活性和高可靠性的数据中心解决方案，在站点发生故障时仍能保持业务连续性。站点之间支持的最大距离约为 435 英里（700 公里）。

在 FlexPod MetroCluster IP 解决方案中，Cisco VXLAN 多站点解决方案允许您互连和集中管理部署在独立的地理位置分散的数据中心中的 VXLAN 交换矩阵。NetApp MetroCluster IP 提供两个 NetApp 存储集群之间的同步复制解决方案，在园区或城域中提供存储高可用性和灾难恢复。该解决方案使您能够在分布式集成基础架构上设计基于 VMware vSphere 的私有云，并提供统一的解决方案，使多个站点能够以与单个站点大致相同的方式运行，同时保护数据服务免受各种单点故障情况的影响，包括完整的站点故障。

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== SnapMirror 主动同步解决方案（适用于 FlexPod MetroCluster IP 解决方案）

使用 NetApp ONTAP 软件中的 NetApp Snapshot 技术，可以使用基于 Snapshot 的备份中的数据快速恢复关键任务 SAN 数据服务。

* 部署在两个不同站点的两个 ONTAP 集群经过对等处理，并配置了 SnapMirror 主动同步，用于同步数据复制和灾难恢复。
* ONTAP 调解器部署在第三个故障域中，如下图所示。与集群一起，ONTAP 调解器完成 SnapMirror 活动同步解决方案的仲裁。
* ONTAP 调解器从对等 ONTAP 集群和节点接收运行状况信息，并在它们之间进行协调以确定其状态。运行状况数据有助于集群区分各种类型的故障，并决定是否执行自动故障转移。


image:dc-tech-spec_image18.png["SnapMirror 主动同步解决方案组件，适用于 FlexPod MetroCluster IP 解决方案"]
